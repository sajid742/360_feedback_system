# Demo data

One organisation, fully interconnected, generated by the existing seed chain.

## Seeding

```bash
npm run db:apply                       # schema + reconcile
npm run db:generate                    # npx prisma@5.22.0 generate
npm run db:seed                        # permissions
# note the `-w apps/api`: the root db:bootstrap-tenant script is itself an
# `npm run`, and the second npm hop drops the flags after `--`.
npm run -w apps/api db:bootstrap-tenant -- --no-starter-content \
  --org "CARE Pvt. Ltd." \
  --slug care --email sajidq@carepvtltd.com --password "Password123!"
npm run db:seed-roles                  # the five system roles + their grants
npm run db:sample                      # org chart, competencies, questionnaire
npm run db:demo                        # the demo dataset
```

`db:seed-roles` runs **after** the bootstrap: it re-seeds roles for organisations
that already exist, so on an empty database it has nothing to do.

`--no-starter-content` matters: without it the tenant gets a second
"Standard 360 Review" questionnaire and an overlapping competency set, because
`db:sample` brings its own.

`db:demo` is idempotent — re-running is a no-op once "Mid-Year Review 2027" exists.
It is also deterministic: a fixed pseudo-random seed means every machine produces
the same numbers, so screenshots and support conversations match.

## Per-quadrant questionnaires and the coverage matrix

A *quadrant* (feedback source — Self, Line Manager, Peer, Subordinate, Parents;
the UI tab is **Sources**) may carry its own questionnaire instead of the
cycle's. The demo data exercises this on purpose, so the **Competency coverage**
matrix at Appraisals → Cycles → open a cycle → **Sources** has something real to
show rather than a grid of identical rows.

The arrangement is: one quadrant on its **own** questionnaire, the rest
inheriting the cycle questionnaire, which yields **one quadrant-specific
competency and six shared ones**.

| Quadrant | Questionnaire | Inherited? |
|---|---|---|
| Line Manager | Standard 360 Review | yes |
| Peer | **Peer Perspective 2027** | **no — quadrant questionnaire** |
| Self | Standard 360 Review | yes |
| Subordinate | Standard 360 Review | yes |

"Standard 360 Review" is the cycle questionnaire: `db:sample` creates it with
four questions (three rating, linked to Strategic Leadership, Effective
Communication and Teaching & Delivery Excellence, plus one open-text question
linked to no competency) and `db:demo` appends three more rating questions for
Decision Making, Collaboration & Teamwork and Student & Parent Engagement —
seven questions, six of them competency-linked. The peer questionnaire carries
two questions: one on **Effective Communication**, worded for peers, and one on
**Knowledge Sharing**, which no other quadrant asks about.

Resulting coverage:

| Competency | Line Manager | Peer | Self | Subordinate | Comparable? |
|---|---|---|---|---|---|
| Effective Communication | 1 q | 1 q | 1 q | 1 q | **Shared** |
| Collaboration & Teamwork | 1 q | — | 1 q | 1 q | **Shared** |
| Decision Making | 1 q | — | 1 q | 1 q | **Shared** |
| Strategic Leadership | 1 q | — | 1 q | 1 q | **Shared** |
| Student & Parent Engagement | 1 q | — | 1 q | 1 q | **Shared** |
| Teaching & Delivery Excellence | 1 q | — | 1 q | 1 q | **Shared** |
| Knowledge Sharing | — | 1 q | — | — | **Quadrant-specific** |

Read it like this. *Effective Communication* is asked of every group, so all four
can be compared on it. *Knowledge Sharing* is asked only of peers — a real
answer, but not a comparison. The other five are compared across three groups; the
Peer column is blank for them because the peer questionnaire never asks about
them. That is **not assessed**, which is a different thing from **withheld**
(asked, answered, but suppressed because fewer than `min_responses_to_show`
reviewers replied).

None of this is stored. "Shared" and "quadrant-specific" are derived from the
questions linked to each quadrant's effective questionnaire, so changing a
quadrant's questionnaire changes the matrix immediately. There is no
quadrant → competency mapping table, screen or setting.

> **Which cycle carries the override, and why.** `db:demo` attaches the peer
> questionnaire (`Peer Perspective 2027`) to the Peer quadrant of the **draft**
> cycle **"Mid-Year Review 2027"**, and creates that cycle's four quadrants at the
> same time. It is deliberately *not* on the running "Annual Review 2026": that
> cycle already holds 2,385 answers collected against the cycle questionnaire, and
> swapping a quadrant's questionnaire underneath answers that have already been
> given is the mistake the manuals warn against. Decide quadrant questionnaires
> while a cycle is in draft.
>
> To see it: Appraisals → Cycles → **Mid-Year Review 2027** → Sources.
>
> Before 2026-08-21 this seed silently did nothing — it looked for a peer quadrant
> on a cycle that had none, skipped the attach behind an `if`, and printed a
> success line anyway. The guard now throws instead.

## Consolidated parent feedback

The draft cycle **Mid-Year Review 2027** also demonstrates the alternative parent workflow.
Its **Parents** quadrant is set to `parent_mode = 'consolidated'` with the questionnaire
**Parent Experience 2027** — one rating question, linked to the competency *Parent Experience*.

Instead of one secure link per (student, teacher), `db:demo` generates **one link per student**
covering every teacher that child has:

| Student | Class | Teachers on the one form |
|---|---|---|
| Ahmed Khan | Grade 4 A | Imran Farooqi, Usman Malik, Sana Javed |
| Ayesha Khan | Grade 4 B | Imran Farooqi, Sana Javed, Tariq Mahmood |
| Bilal Khan | Grade 5 A | Imran Farooqi, Bilal Ahmed, Sana Javed |

Three forms, nine teacher ratings, all `pending` — the parents have not answered yet, so the
admin screen has outstanding work to show and the tracking columns are not all green.

Each row in `evaluation_link_targets` carries its own `reviewer_assignment_id`, so when a parent
does answer, each rating lands on that teacher's own assignment. Scoring, the Parents quadrant
weight and the anonymity threshold are all evaluated **per teacher**, exactly as they are for the
standard per-teacher links on *Annual Review 2026*.

> **The two modes coexist deliberately.** *Annual Review 2026* keeps the original per-teacher
> links with their collected answers; *Mid-Year Review 2027* demonstrates the consolidated form.
> Nothing in the seeded history was rewritten to add this.

> As with the per-teacher links, the raw tokens are discarded — only the SHA-256 hash is stored —
> so none of the three demo forms can be opened at `/evaluate/:token`. Generate a fresh one from
> **Parent Evaluations** to walk the parent journey.

## Deliberate gaps

These are demonstration features, not bugs:

- Several quadrants sit **below the 3-response anonymity threshold** and show as
  Confidential. A Line Manager quadrant has one reviewer by definition, so it is
  always suppressed at the default threshold — lower it in
  Settings → Feedback Rules to show it.
- The active cycle is **mid-flight** (357 submitted, 23 in progress, 34 pending),
  so completion is not 100% and the pending-reviews drill-down has content.
- eNPS runs as its own **Engagement Pulse** cycle on a 0–10 scale, because rating
  validation uses the cycle's scale — an eNPS question inside the 1–5 review
  questionnaire would make that questionnaire unsubmittable.
